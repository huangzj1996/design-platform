# LeaferJS 编辑状态与撤销重做

<!-- cspell:words zzalai otaku Zundo partialize -->

**LeaferJS 2.3.4 提供实现历史记录所需的场景事件和 JSON 导入导出。** 官方编辑器历史页说明了如何采集变更。核对 `@leafer-in/editor@2.3.4` 发行包的公开类型和源码后，未发现内置的 `undo()`、`redo()`、命令分派或设计稿快照管理 API。社区已有直接操作 Leafer 节点的命令栈，也有使用快照历史的 Leafer 海报编辑器实践。[官方历史记录](https://www.leaferjs.com/ui/plugin/in/editor/Editor/history.html) · [官方编辑器 2.3.4 发行包](https://registry.npmjs.org/@leafer-in/editor/-/editor-2.3.4.tgz) · [海报编辑器作者的实践](https://www.leaferjs.com/ui/en/blog/2026-03-20.html#_3-undo-redo)

## LeaferJS 自带的能力

| 能力       | LeaferJS 的接口                                                                                                                              | 对设计稿编辑的含义                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 执行操作   | `app.editor` 支持选择、编组、移动和变换。`Editor` 通过 `TransformTool` 对当前图形执行变换。                                                  | 图层树或属性面板的操作可以表达为按元素 `id` 修改文案、排序或移动到指定容器等设计稿命令。应用负责检查这些操作是否合法。[Editor API](https://www.leaferjs.com/ui/plugin/in/editor/) · [Editor 源码](https://github.com/leaferjs/leafer-in/blob/main/packages/editor/src/Editor.ts)                                                                                                                                                                         |
| 监听变更   | 官方建议用编辑器的 `drag.start` 和 `drag.end` 划分手势，在 `app.tree` 收集 `PropertyEvent` 和 `ChildEvent`。选中和变换还有各自的编辑器事件。 | 一次变换可以产生多次属性变更。场景事件可用于采集交互结果，订阅设计稿提交可以让画布、图层树和保存流程读取同一次编辑的结果。[官方历史记录](https://www.leaferjs.com/ui/plugin/in/editor/Editor/history.html) · [PropertyEvent](https://www.leaferjs.com/ui/en/reference/event/basic/Property.html) · [ChildEvent](https://www.leaferjs.com/ui/en/reference/event/basic/Child.html) · [编辑器事件](https://www.leaferjs.com/ui/plugin/in/editor/Event.html) |

## LeaferJS 生态中的实践

- **`state-snapshot` / `StateShot`。** Leafer 海报编辑器作者将稿定开源的 StateShot 改写为 TypeScript，用于撤销重做。`History` 提供 `pushSync`、`undo`、`redo`、`onChange` 和容量限制。默认按块序列化并按哈希复用数据，对已经不可变的状态可关闭 `useChunks`，直接保存引用。这个库适合已有文档提交入口、只需要补历史栈的应用。命令校验和一次编辑的提交时机由应用决定。[海报编辑器作者的实践](https://www.leaferjs.com/ui/en/blog/2026-03-20.html#_3-undo-redo) · [state-snapshot API](https://github.com/Xdy1579883916/state-snapshot#api) · [StateShot 源码](https://github.com/gaoding-inc/stateshot)
- **`@zzalai/leafer-undo-redo`。** 由 `otaku1951` 发布。`CommandManager` 保存命令对象，调用 `execute()` 和 `undo()`，重做再次调用 `execute()`，批量命令按逆序撤销。已弃用的 `leaferjs-undo-redo@1.0.2` 由同一发布者维护，和 scoped `1.0.3` 的 `dist/src` JavaScript 文件逐一对比一致。两版的 `RemoveElementCommand` 保存了原索引，撤销时却通过 `parent.add()` 追加，无法保证恢复原有同级顺序。scoped `1.0.3` 的包声明还把含 ESM 导出的 `.js` 入口标为 CommonJS，`module` 指向发行包缺少的 `.mjs`。这套实现可以参考如何组织场景操作的命令栈，当前发行包有集成障碍。[旧包的弃用声明](https://www.npmjs.com/package/leaferjs-undo-redo) · [旧包 1.0.2 发行包](https://registry.npmjs.org/leaferjs-undo-redo/-/leaferjs-undo-redo-1.0.2.tgz) · [scoped 1.0.3 发行包](https://registry.npmjs.org/@zzalai/leafer-undo-redo/-/leafer-undo-redo-1.0.3.tgz)
- **Leafer Flow。** 这个流程图编辑器的架构文档描述了 `DocumentStore` 持有自己的版本化文档、`DocumentCommands` 提供编辑入口、Leafer 适配器负责渲染和回读交互结果，`Editor` 协调历史与自动保存。它提供了用 Leafer 渲染独立文档模型的同类应用实例。[Leafer Flow 架构说明](https://github.com/2992362310/leafer-flow#架构概览)

## 其他编辑状态实现

| 实现                | 可参考的做法                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Lexical**         | `dispatchCommand` / `registerCommand` 处理编辑意图，提交后产生不可变的 `EditorState`，`registerUpdateListener` 接收更新。`@lexical/history` 注册撤销重做命令，通过更新监听记录或合并快照。它的快照包含富文本节点树和选区，可参考接口关系。[命令](https://lexical.dev/docs/concepts/commands) · [Editor State](https://lexical.dev/docs/concepts/editor-state) · [更新监听](https://lexical.dev/docs/concepts/listeners) · [历史源码](https://github.com/meta/lexical/blob/main/packages/lexical-history/src/index.ts) |
| **Zustand + Zundo** | Zustand 的 `createStore` 提供框架无关的 `getState` 和 `subscribe`。Zundo 的 `temporal` 可用 `partialize` 只记录设计稿，用 `equality` 跳过无实际变化的更新，并设定记录上限。编辑入口、拖动或连续输入何时提交，仍由应用定义。[Zustand createStore](https://zustand.docs.pmnd.rs/reference/apis/create-store) · [Zundo 选项](https://github.com/charkour/zundo#exclude-fields-from-being-tracked-in-history)                                                                                                             |
| **Redux / Immer**   | Redux 官方撤销示例用 `past`、`present`、`future` 包装 reducer，以状态引用记录历史。需要存差异时，Immer 的 `produceWithPatches` 提供正向和逆向补丁。两种做法都可以沿用应用的文档类型，历史仍以应用的提交边界为准。[Redux 撤销历史](https://redux.js.org/usage/implementing-undo-history) · [Immer Patches](https://immerjs.github.io/immer/patches/)                                                                                                                                                                   |

## 与本仓库的适配

当前桌面端用 `leafer-ui@2.3.4`，画布从设计稿生成 Leafer 场景，点击通过元素 `id` 回传选区。`App` 的 `commitEdit` 校验后更新当前标签页设计稿，`editDocument` 推进持久化编辑版本，自动保存读取该版本的文档。当前这条编辑链路仍使用 `legacy` 的版本 1 类型和校验，`design-schema` 已单独提供 v2 契约。[依赖锁定](../../pnpm-lock.yaml) · [画布适配](../../apps/desktop/src/electron-render/leafer-canvas.ts) · [文档提交](../../apps/desktop/src/electron-render/App.tsx) · [编辑状态](../../apps/desktop/src/electron-render/editor-state.ts) · [自动保存](../../apps/desktop/src/electron-render/use-autosave.ts) · [v2 设计稿接口](../../packages/design-schema/src/v2.ts)

针对接入 v2 后的编辑链路，建议让操作入口按元素 `id` 更新设计稿，画布、图层树和属性面板读取同一次提交。历史可按标签页保存有限数量的设计稿快照。拖动过程中由画布预览，结束时提交一次文档修改。撤销或重做后把恢复的文档交给原保存流程，检查当前选区指向的元素是否仍存在。若先沿用 React 状态，Redux 的历史示例就可以作为参考。若确实需要 React 之外的订阅接口，再评估 Zustand + Zundo。采用引用快照时，需在实际提交链路验证未修改分支能否保留引用，避免把局部更新等同于整个校验流程的结构共享。[文档编辑函数](../../packages/editor-core/src/document/edit.ts) · [工作区和标签页](../../apps/desktop/src/electron-render/workspace.ts) · [Redux 撤销历史](https://redux.js.org/usage/implementing-undo-history) · [Zustand createStore](https://zustand.docs.pmnd.rs/reference/apis/create-store)

调研核对了官方文档、公开源码和 npm 发行包内容。社区包尚未在本仓库的 Electron/Vite 环境中运行验证。
