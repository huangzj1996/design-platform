# React 可编辑画布选型

**已决定使用 LeaferJS 作为首版 Canvas 渲染和图形交互内核。** Electron 渲染端把版本 1 JSON 元素树映射到 LeaferJS 场景。React 负责画布容器、图层树和属性面板，编辑核心继续维护设计稿。[桌面设计编辑器 MVP 规格](https://github.com/huangzj1996/design-platform/issues/9) · [LeaferJS 图形编辑器](https://www.leaferjs.com/ui/plugin/in/editor/)

下文是方案研究和建议。接入成本根据项目规格与官方文档估算。Electron 完整交互、打包和性能仍待验证。

## 选型依据

首版在 Electron Forge + Vite 中使用 React。画布、图层树和属性面板读写同一个设计稿，按稳定的 `id` 定位元素。父元素的 `children` 表达层级和顺序，元素记录内容、布局和样式。验收包括在画布与图层树之间同步单选、创建标题和带子元素的容器、局部编辑文案、间距和颜色，以及删除容器及其后代。已确认的元素树契约包含将来移动元素时保留 `id` 的语义，当前规格未要求画布拖拽、缩放、旋转、框选或画布内联文字编辑。[桌面设计编辑器 MVP 规格](https://github.com/huangzj1996/design-platform/issues/9) · [元素树与编辑契约](https://github.com/huangzj1996/design-platform/issues/3#issuecomment-7073632638)

画布方案影响预览和编辑交互。自动保存按原有规格消费编辑核心提交的设计稿快照，由 Electron 主进程处理指纹、写入队列和关闭或切换前的保存。选区不参与写入，重开时清空。Agent 生成、独立导出和撤销另有范围安排。[桌面设计编辑器 MVP 规格](https://github.com/huangzj1996/design-platform/issues/9)

## LeaferJS 接入方案

首版使用 LeaferJS 的 Canvas 2D 场景树和官方编辑插件。如果后续要引入移动、调整尺寸和旋转，LeaferJS 的官方编辑插件已提供选择框与交互，能减少自建交互的工作。首版只用到其中的单选和高亮。画布基础包和官方插件仓库均标为 MIT。[LeaferJS 仓库](https://github.com/leaferjs/LeaferJS) · [图形编辑器](https://www.leaferjs.com/ui/plugin/in/editor/) · [官方插件许可证](https://github.com/leaferjs/leafer-in/blob/main/LICENSE)

- **React 管理外壳，LeaferJS 管理场景。** 在画布组件挂载时把 `App` 绑定到容器，用 ref 保存实例，卸载时销毁。可将内容放在 `app.tree`，将编辑反馈交给 `app.editor`。监听 `EditorEvent.SELECT`，把选中的 Leafer 节点映射到版本 1 元素 `id`，从图层树选中时再调用编辑器的选中接口。按相同 `id` 判断是否需要同步，避免反复触发选中事件。[在 React 中使用](https://www.leaferjs.com/ui/guide/framework/react/) · [App 结构](https://www.leaferjs.com/ui/en/guide/advanced/app.html) · [EditorEvent](https://www.leaferjs.com/ui/en/plugin/in/editor/event/EditorEvent.html)
- **设计稿仍由编辑核心持有。** 属性面板把文案、间距、颜色及元素增删提交给编辑核心，更新后的设计稿再同步到 Leafer 场景。保存和重开沿用现有版本 1 JSON。Leafer 自带的 `toJSON()` 序列化的是其场景节点，包含它定义的 `tag` 和绘制字段。[桌面设计编辑器 MVP 规格](https://github.com/huangzj1996/design-platform/issues/9) · [Leafer JSON 文档](https://www.leaferjs.com/ui/en/reference/UI/json.html)
- **排版与编辑联动是主要验证项。** `@leafer-in/flow` 支持方向、间距、内边距和换行。官方说明它尚未完整适配图形编辑器，频繁变更也可能影响性能。首版可以先用普通 `Group` 或 `Box` 配合按元素树计算的位置和尺寸。若要用 Flow，优先验证嵌套文本换行后的重排、直接点选子元素、图层树双向选中，以及删除容器后重开 JSON 的结果。[Flow 文档](https://www.leaferjs.com/ui/en/plugin/in/flow/) · [Editor 状态](https://www.leaferjs.com/ui/en/plugin/in/editor/Editor/state.html)

## React Konva 备选实现

在 Canvas 2D 的几种路线里，原生 API 提供绘图、测量和像素操作，应用要自己维护节点、命中和重绘。Fabric.js 提供可变的画布对象和现成的交互式文字 `IText`，适合直接操作对象成为重点的编辑器。React Konva 用 JSX 描述场景节点，可以实现「编辑核心更新 JSON，React 根据 JSON 重绘」数据流。[HTML Canvas 2D 规范](https://html.spec.whatwg.org/multipage/canvas.html#the-2d-rendering-context) · [Fabric.js IText](https://fabricjs.com/api/classes/itext/) · [React Konva](https://konvajs.org/docs/react/index.html)

1. **先计算布局，再绘制。** 版本 1 JSON 继续保存元素标识、父子关系、顺序、内容、布局参数和样式。渲染端根据这些参数和约定的逻辑画板宽度算出各元素的 `x`、`y`、宽、高，然后映射到 `Stage → Layer → Group`。容器用 `Group` 和背景 `Rect`，标题和正文用 `Text`。计算出的几何是渲染结果，自动保存仍取设计稿快照。[元素树与编辑契约](https://github.com/huangzj1996/design-platform/issues/3#issuecomment-7073632638) · [React Konva](https://konvajs.org/docs/react/index.html) · [Konva 组](https://konvajs.org/docs/groups_and_layers/Groups.html)
2. **验证简单嵌套布局。** 建议第一个样稿采用纵向排列、内边距和子元素间距。一个宽 600 px、内边距 16 px 的容器，能给文本 568 px 的内容宽度。若两个子元素高度分别为 28 和 24 px、间距为 12 px，容器总高为 96 px。把间距改到 24 px，第二个子元素及后续布局应下移相应距离。用同一字体、宽度和换行规则测量并绘制文本，避免多行高度估算误差。只有首版确实需要通用 Flexbox 规则时，再比较手写布局和 Yoga 的接入代价。[Konva 文本测量与换行](https://konvajs.org/docs/shapes/Text.html) · [Yoga 布局树](https://www.yogalayout.dev/docs/getting-started/laying-out-a-tree)
3. **画布只负责命中与反馈。** 将命中的 Konva 节点映射到元素 `id`。点子元素选中子元素，点容器留白选中容器，点画板空白清空选区。画布与图层树共用一个选中 `id`。属性面板用原生输入控件提交增删改，Canvas 重绘对应元素。选区和高亮保留在界面状态中。若后续要双击画布编辑文字，可在文字位置覆盖 HTML 输入框，使用浏览器的文字输入能力。[Konva 空白点击](https://konvajs.org/docs/events/Stage_Events.html) · [事件冒泡](https://konvajs.org/docs/events/Cancel_Propagation.html) · [Konva 可编辑文本示例](https://konvajs.org/docs/sandbox/Editable_Text.html)
4. **区分视口和设计稿坐标。** Canvas 按可见视口设置尺寸，滚动或平移改变画板在视口里的偏移。Konva 按设备像素比处理清晰度。未来加入缩放时，仍用逻辑坐标定位元素。长页面先验证正常尺寸的视口，视图性能达到瓶颈后再测量是否需要裁剪视口外的元素。[Konva 响应式画布](https://konvajs.org/docs/posts/responsive-canvas.html) · [Konva 性能指南](https://konvajs.org/docs/performance/All_Performance_Tips.html)

建议用一份有两层容器和中文长文本的样稿验证三件事。改文案导致换行后，后续元素的位置随之更新。点击子元素和容器留白能分别选中正确的层级。仅滚动或切换选区时指纹保持不变，修改布局后重开原 JSON 能还原编辑结果。首版验收继续使用已确认的 Electron 应用入口。[首版端到端验收决议](https://github.com/huangzj1996/design-platform/issues/8#issuecomment-7074873425)

## DOM 备选方案的接入方式

1. **`packages/design-schema` 定义版本 1 契约。** 负责元素树结构、元素标识唯一性、子元素顺序和打开时的校验。渲染端按已定义的字段把布局与样式映射到已知的 CSS 属性。布局仍由设计稿描述。[桌面设计编辑器 MVP 规格](https://github.com/huangzj1996/design-platform/issues/9)
2. **`packages/editor-core` 持有并修改当前设计稿。** 提供按元素 `id` 定位的新增、局部更新和删除操作，保留其他字段与兄弟元素顺序。删除容器时移除整个子树，一次提交更新后的文档。使用现有包作为视图和文件流程之间的边界。[元素树与编辑契约](https://github.com/huangzj1996/design-platform/issues/3#issuecomment-7073632638) · [桌面设计编辑器 MVP 规格](https://github.com/huangzj1996/design-platform/issues/9)
3. **在 `apps/desktop` 的 React 渲染端从同一份状态派生三个视图。** 画布按 `children` 递归渲染标题、容器和子元素。节点使用稳定 `id` 作为 `key`，并用单独的 `data-element-id` 标记事件目标。画布点击选中最近的元素节点，点画布空白处清空。图层树使用同一个选中 `id`，属性面板按该 `id` 从当前设计稿读取字段并向编辑核心提交修改。删除使选中元素消失时同步清空选区，成功打开另一份设计稿时从空选区开始。将选中轮廓作为渲染端样式，避免改动元素的盒尺寸。[React 列表渲染](https://react.dev/learn/rendering-lists) · [React 事件传播](https://react.dev/learn/responding-to-events) · [桌面设计编辑器 MVP 规格](https://github.com/huangzj1996/design-platform/issues/9)
4. **自动保存从文档提交获取快照。** 画布选中和悬停可以立即反馈。提交局部修改或增删元素后，正常触发文档保存流程。未来添加拖拽时，可把拖动中的位置和落点作为临时预览，松手后再一次提交树结构或布局变更。[桌面设计编辑器 MVP 规格](https://github.com/huangzj1996/design-platform/issues/9) · [dnd-kit 拖放完成与取消](https://dndkit.com/react/guides/multiple-sortable-lists/)

已有 JSON 往返时，建议用一份多层容器样稿验证视图与文件的一致性。画布和图层树连续选中同一子元素，修改文案、间距和颜色，再删除整个容器并重开。核对剩余元素的 `id`、顺序与未修改字段，以及单纯切换选区是否跳过写入。这些行为已在首版规格中列为验收内容。[桌面设计编辑器 MVP 规格](https://github.com/huangzj1996/design-platform/issues/9)

## 局限和重评条件

- **嵌套拖放进入范围。** 先在 DOM 方案中评估 dnd-kit。它的官方示例覆盖跨列表移动。此处还需定义任意嵌套下的落点、合法父节点和防止移入自身后代的规则，并在放下时一次提交两个容器的 `children` 变更。如果只需同容器排序，可只更新当前容器的子元素顺序。[dnd-kit 跨列表](https://dndkit.com/react/guides/multiple-sortable-lists/) · [元素树与编辑契约](https://github.com/huangzj1996/design-platform/issues/3#issuecomment-7073632638)
- **DOM 需要缩放及变换手柄。** 基于实际的滚动容器、缩放与嵌套坐标验证选区绘制和落点换算。浏览器 `getBoundingClientRect()` 返回视口坐标。采用覆盖层时，需要换算到画布容器所在坐标系。只有设计稿支持相应自由布局字段时，才把 Moveable 的变换结果写回元素。[CSSOM View](https://drafts.csswg.org/cssom-view/#dom-element-getboundingclientrect) · [Moveable](https://github.com/daybrush/moveable)
- **自由图形或大场景成为主要工作量。** 用同一份代表性设计稿比较启动、缩放、平移和选择的实际表现，再决定是否为自由图形引入 Konva 或 Fabric.js。Konva 的组提供坐标变换，文本内联编辑的官方示例使用 HTML `textarea`。如果页面布局与自由图形同时重要，也可先评估只用 Canvas 渲染某类元素。[React 性能工具](https://react.dev/reference/dev-tools/react-performance-tracks) · [Konva 组](https://konvajs.org/docs/groups_and_layers/Groups.html) · [Konva 可编辑文本示例](https://konvajs.org/docs/sandbox/Editable_Text.html)
- **完整页面搭建器的交互成为优先项。** 评估 Puck 时，用已存在的版本 1 样稿试验 `children` 到 `slot` 的双向映射，检查稳定 `id`、属性局部更新与切换文件的行为。由于 `data` 是初始值，外部编辑和打开文件都要有明确的同步方案。若最终方向是白板，则需用 tldraw 验证自定义形状及本地打包后的许可行为。[Puck 组件 API](https://puckeditor.com/docs/editor/api-reference/components/puck#data) · [Puck Slot](https://puckeditor.com/docs/editor/api-reference/fields/slot) · [tldraw 形状](https://tldraw.dev/sdk-features/shapes) · [tldraw 许可](https://tldraw.dev/community/license)
