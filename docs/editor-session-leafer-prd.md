# PRD · 编辑器会话与 LeaferJS 适配

## 问题陈述

用户需要在桌面端打开已定义的 v2 设计稿，在画布、图层树和检查器中编辑同一份内容，并能撤销、重做和保存。当前桌面编辑链路还使用旧版设计稿模型。画布可以将已有五类元素映射到 LeaferJS，画布交互、选区和设计稿提交仍分别由桌面端协调。接入 v2 需要让一次编辑在三个界面里产生一致的结果，并让历史保留变量引用、布局声明、元素身份和同级顺序。

## 解决方案

每份打开的设计稿由一个编辑器会话管理。画布、图层树和检查器读取同一份快照，通过命令提交变更。用户拖动自由定位的元素时，画布实时预览位置，松手后提交一个可撤销的编辑。保存和重新打开使用同一份 v2 设计稿，LeaferJS 根据设计稿及其布局结果生成画布节点。

5. 作为设计者，我希望在画布点选元素时图层树和检查器同步更新，以便确认当前操作对象。
6. 作为设计者，我希望在图层树点选元素时画布也显示对应选区，以便找到嵌套在容器里的对象。

8. 作为设计者，我希望在不同标签页之间切换时保留各自的选区，以便继续处理原来选中的元素。
9. 作为设计者，我希望每个标签页记住检查器的展开状态，以便按每份设计稿的需要使用编辑区。
10. 作为设计者，我希望拖动时看到元素随指针移动，以便判断落点。

14. 作为设计者，我希望直接拖动后保存明确的落点数值，以便再次打开时得到同样的位置。
15. 作为设计者，我希望一次拖拽只需撤销一次，以便回到手势开始前的位置。

17. 作为设计者，我希望重做恢复已提交的拖拽结果，以便找回刚撤销的操作。
18. 作为设计者，我希望切换选区或展开检查器后仍能撤销上一次设计稿编辑，以便随时检查其他元素。
19. 作为设计者，我希望在当前标签页撤销时只影响当前设计稿，以便独立编辑多份设计稿。
20. 作为设计者，我希望删除或撤销导致元素树变化后选区仍然有效，以便检查器始终指向可编辑的元素。
21. 作为设计者，我希望撤销删除时元素回到原父容器和原顺序，以便恢复原图层结构。
22. 作为设计者，我希望无效编辑能获得明确诊断，以便修正操作并保留上一次有效结果。
23. 作为设计者，我希望保存反映最后一次提交、撤销或重做后的设计稿，以便磁盘内容和画布一致。
24. 作为设计者，我希望重新打开保存的设计稿时保留元素 ID、层级、顺序和设计声明，以便接着编辑。
25. 作为编辑器开发者，我希望画布、图层树和检查器共用命令入口，以便同一种编辑遵守同样的规则。
26. 作为编辑器开发者，我希望从指定快照按 ID 查询任意层级的元素，以便同一次渲染使用同一版数据。
27. 作为编辑器开发者，我希望分别读取单选元素和有序多选结果，以便正确展示检查器内容。
28. 作为编辑器开发者，我希望查询元素的直接父元素，以便从快照定位元素在树中的上下文。
29. 作为编辑器开发者，我希望按名称读取所有精确匹配的元素，以便处理不同容器中的同名元素。

32. 作为编辑器开发者，我希望以 `DesignDocument`、`DesignElement` 等统一命名使用当前契约，以便无需在代码命名中维护版本后缀。

## 实现决策

- `editor-core` 负责编辑器与设计稿 DSL 的桥接。`createEditorSession(document)` 为一个打开的设计稿创建独立会话，提供 `dispatch`、`getSnapshot`、`subscribe` 和 `selectors`。状态管理用纯 TypeScript 实现。
- `DesignDocument` 是设计稿内容的唯一数据源，元素树位于 `document.children`。快照包含不可变的设计稿、有序的 `selectedElementIds` 和检查器展开状态。同一状态的连续读取返回同一个快照对象。
- `session.selectors` 只负责节点查询。每个查询显式接收快照。按 ID 返回元素。恰好选中一个元素时，单选查询返回该元素。多选查询按选区 ID 顺序返回所有选中元素。父元素查询返回直接父元素，顶层元素或未知 ID 返回 `undefined`。名称查询精确匹配，按元素树顺序返回全部同名元素。
- 命令用带 `type` 的数据对象表示。选择、检查器开合、设计稿编辑、撤销和重做统一由 `dispatch` 处理。设计稿编辑在发布前通过 DSL 校验。一次有效变更原子发布一个快照并通知订阅者。无效命令返回诊断，快照和历史保持原样。没有实际变化的操作保留当前快照。
- 设置选区时按传入顺序去重并保留有效 ID。提交设计稿编辑、撤销或重做后，保留仍然存在的选中元素。撤销恢复的元素沿用原 ID 和树位置。
- 历史栈按会话保存有限数量的不可变设计稿快照。选区和检查器开合可以发布快照。历史和自动保存只跟踪设计稿内容，撤销和重做以恢复后的完整设计稿参与保存。
- `@design-ai/editor-core/leafer` 复用现有设计稿布局结果，返回可挂载的 LeaferJS 节点树。容器保留层级和顺序。矩形、椭圆、文本和图标保留各自的绘制含义。画布命中目标关联原设计稿元素 ID，包括由多个绘制节点构成的图标。
- 桌面端负责画布挂载、交互、视口与文件操作。拖拽过程在画布预览。松手后，适配器把落点换算到父容器内容区的设计稿坐标，桌面端提交一条移动命令。顶层元素使用设计稿画布坐标。只更新发生变化的轴。该轴存在坐标变量引用时，提交落点数值，保留变量定义与其他轴的声明。
- 当前 DSL 的类型、函数和源码文件使用无版本后缀的命名。`DesignDocument`、`DesignElement`、`parseDesignDocument`、`validateDesignDocument` 和 `layoutDesignDocument` 表示当前契约。保存的 JSON 继续以 `version: 2` 标识格式。

## 测试决策

- 以桌面端正常的打开、编辑和保存入口作为验收接缝。测试关注用户能观察到的渲染结果、选区、坐标、历史和文件内容。
- 验收使用一份真实的 v2 设计稿，包含容器、矩形、椭圆、文本和图标，至少有一个嵌套在自由布局容器中的矩形以及坐标变量引用。打开后确认五类元素渲染，验证画布、图层树和检查器的选区同步，完成拖动、撤销、重做、保存和重新打开。核对只变化的坐标轴、恢复的变量引用、保留的元素 ID 与顺序，以及最终文件的版本和位置。
- 通过 `createEditorSession` 的公开接口验证命令、快照、查询和订阅。覆盖两份设计稿各自的历史和检查器，订阅者在提交时观察到一致快照，无效命令和无变化命令保持状态，删除后清理失效选区，同名查询与父元素查询正确返回。
- 通过 LeaferJS 适配器的公开入口验证五类元素能生成可挂载节点、嵌套顺序和元素 ID 能传到画布、嵌套自由布局的落点能正确转换。拖动预览和正式提交的效果通过桌面编辑流程验证。
- 沿用仓库已有的设计稿编辑测试、可注入画布引擎的渲染测试、桌面编辑流程测试以及基于临时文件的读写测试作为先例。

## 范围之外

- 自动布局容器内的拖拽排序、跨容器拖拽和批量变换。
- 将拖拽中的预览坐标实时同步到其他面板。
- 持久化撤销栈或在关闭后恢复选区和检查器展开状态。
- 原生 v1 设计稿迁移、Pencil 导入器的格式改造和 DSL 字段扩展。

## 补充说明

- 会话重用设计稿布局与校验。LeaferJS 的场景 JSON 可用于场景序列化，正式保存和撤销重做基于设计稿快照，以保留其变量与布局声明。
- 表达多选的状态和查询属于首版会话契约。桌面端的具体多选编辑操作可通过后续需求扩展。
